## Traps
- `CNAME` must stay in the repository root or the custom domain drops.
- The capability statement PDF is generated from `capability-statement.html` and the one-page overview (the slick sheet) from `slick-sheet.html`, both by `scripts/render.js`, which also sets the PDF Author with `scripts/pdf-metadata.py` (needs `pypdf`). Do not edit the PDFs. The capability statement is two pages and the overview is one; the render script and CI fail on any other count. The overview's QR code (`assets/img/qr-site.svg`, made with `segno`) and acquisition-cycle diagram (`assets/img/acquisition-cycle.svg`) are generated by short Python snippets, not drawn by hand; regenerate rather than edit. The share image `assets/img/og.png` comes from `scripts/og.html`; change its copy when the headline changes.
- Facts appear in several files. Change `records/facts.md` first, then grep for the old value.
- GitHub Pages tells browsers to cache files for ten minutes, so a changed stylesheet or script can run against a stale copy of the other. Every CSS and JS link carries a content hash (`?v=...`). After editing anything in `assets/css` or `assets/js`, run `python3 scripts/stamp.py` and commit the page changes with it; CI fails if the stamps are stale.
- `404.html` uses absolute asset paths and looks unstyled when opened from disk. That is expected.
